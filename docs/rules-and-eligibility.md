## Originality, AI help and attribution

The official rules require a newly created challenge project and exclude pre-existing projects, prior coursework and earlier hackathon entries. Public libraries, datasets and pretrained models are allowed. AI assistance is explicitly permitted and encouraged, while the work must remain the team's own. Submitted content must be authorised; confidential or personal data must not be uploaded. Teams retain their IP and permit Databricks to showcase the submission. Misrepresentation or plagiarism can disqualify a team.

This project should credit Shivam Gupta as project owner and presenter, and describe AI-assisted research and implementation honestly. Do not claim interviews, manual implementation, modifications, tests, field verification, deployment or measured impact that did not occur. Dataset, library, model and template credits belong in the repository and submission. Shivam must be able to explain and demonstrate the submitted system.

The published schedule includes a 12–26 October mentored build sprint. The rules require a new project created for this challenge; they do not explicitly prohibit starting a new project after the 16 September announcement and before the sprint. Preserve the new project's history rather than presenting old work as new.

## Databricks and data requirements

Use at least one Singapore public/open dataset and run the platform work on Databricks. Local development and deployment artifacts are useful preparation, but do not establish that an end-to-end Databricks run occurred. Record the actual workspace run evidence before making that claim.

The guide describes Free Edition as non-commercial, quota limited and without an SLA. Use it for the challenge; any commercial roadmap must budget for an appropriate production service. Keep compute small, avoid idle endpoints and deploy the real path early. Explicitly identify local snapshots, cached results, planning assumptions and prototype features.
